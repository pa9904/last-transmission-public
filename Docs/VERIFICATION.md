Unity 6000.6.7f1에서 Windows x64 Mono 플레이어를 빌드했습니다. 에디터 검증 40,513개를 통과했습니다. 응답 조합 729개에 마지막 결정 세 가지를 적용한 결과는 목소리 729개, 침묵 1,377개, 새벽 81개입니다.

개발 중 자동 저장 파일 교체가 한 차례 실패했습니다. 완전히 쓴 임시 파일이 남아 있으면 최대 세 번 짧게 재시도합니다. 계속 실패하면 기존 저장 실패 안내를 표시합니다. 음향 조합은 재생 경로를 검증했으며 스피커·헤드폰 청취 평가는 남아 있습니다.

최종 빌드는 1280×800과 1600×900에서 교신 6건, 엔딩 3종, 승인 철회, 저장 복원, 새 프로세스 이어하기를 모두 통과했습니다. 각 실행 및 이어하기 로그에서 예외를 검사했습니다.

## 빌드 실행 검증

실제 Windows 플레이어를 보이는 창으로 실행한 자동 검증에서 상황판 12개 입력, 수동 색 송신, 거짓 보고 거절, 실제 보고 승인, 엔딩 3종, 새 프로세스에서 교신 4 지점과 설정 복원을 확인했습니다.

결과 폴더: `Artifacts/Player-v02-1600x900/`, `Artifacts/Player-v02-1280x800/`. player-report.txt와 ResumeProfile/resume-report.txt, 타이틀·지도·상황판·출입·엔딩 PNG를 보관합니다. 이 자동 검증은 게임의 실제 진행 메서드를 사용하며, UI 마우스 검증과는 구분합니다.

배포 점검 스크립트는 이번 실행 시작 이후에 생성된 보고서와 모든 캡처의 시각을 검사합니다. 이전 실행의 성공 파일이 남아 있어도 새 검증으로 인정하지 않습니다.

## 실제 마우스 조작 점검

1280×800 게임 창을 직접 조작해 확인했습니다.

- 새 게임 → 안내 → 새 관제실 → B 상황판 열기.
- 위치와 구조 경로를 선택하고, 저장 파일에 두 선택이 그대로 기록되는지 확인.
- 상황판에서 근거 원문 버튼을 눌러 해당 지도 문서로 이동.
- 자동 진행으로 만든 별도 최종 저장(미확인 정문 승인 3건)에서 이어하기.
- 빨강 → 초록 → 빨강을 마우스로 송신하고 서로 다른 두 출입구의 보고 확인.
- 틀린 정문 보고를 채택했을 때 신원 승인과 잠금이 유지되는지 확인.
- 일치한 동쪽 보고를 채택한 뒤에도 기존 승인 철회 전에는 정비구 개방이 막히는지 확인.
- 승인 취소 → 정비구 개방 → 확인창 → 좋은 엔딩까지 도달.

이 점검은 새 조작과 최종 분기의 UI 확인이며, 처음 보는 사람이 전편을 플레이한 시간 측정이 아닙니다. 관제실 안내 문구와 상황판 이름이 겹치던 문제를 수정했고, 배포 전 크레딧에도 AI 생성 배경과 직접 작성한 UI를 구분했습니다.

11월 13일의 추가 크레딧 화면 수동 점검은 사용자 Esc 입력으로 중단되었습니다. 크레딧 문구 수정의 컴파일은 완료했지만 그 추가 화면 조작까지 통과했다고 기록하지 않습니다. 11월 15일에는 화면 조작 없이 검증된 빌드의 파일·라이선스·원격 커밋·배포 ZIP을 정리했습니다.

점검 중 입력 직후의 즉시 Windows 캡처에서 일부 고정 문구가 빠졌다가 다음 관측에서 정상으로 보이는 현상을 발견했습니다. 가려진 배경 UI의 렌더링 제거, 글리프 사전 준비와 크기·색별 텍스트 스타일 분리를 적용했지만 드래그 직후 캡처에서는 재현됩니다. 게임 렌더와 캡처 타이밍 중 원인은 분리하지 못했으며 완전 해결로 기록하지 않습니다. 정상 상태의 게임 내부 PNG와 이후 Windows 관측에서는 전체 문구가 표시됩니다.
